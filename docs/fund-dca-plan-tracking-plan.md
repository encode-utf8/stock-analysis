# 基金定投计划：持有金额按期自增与断档补齐方案

- 文档版本：v1.0（2026-09-14）
- 关联文档：`docs/fund-position-caliber-plan.md`（配对口径模型，本方案沿用它）、`docs/fund-positions-plan.md`、根 `checklist.md`
- 分支：`feature/fund-dca-plan`
- 需求原文：定投的基金应该做到持有金额按期自增，如果期间服务器中断没有运行，也应该能够自行补齐，从而正确显示用户重新运行项目后的收益状况。

## 1. 需求确认（用户 2026-09-14 答复）

| 议题 | 结论 |
| --- | --- |
| 手动校对 | 定投之后仍要保留手动修改校对的余地 |
| 统计范围 | 只做「在系统上开启定投计划之后」的更新，**不回溯**启用日之前的期次；有没有底仓不重要，不建模底仓 |
| 频率 | 每日 / 每周（可选星期几）/ 每两周 / 每月 |
| 已有改动 | 先把现有改动提交，再开新分支做本功能 |
| 必须可取消（追加） | 定投必须能取消，不能设置之后就无法取消 |
| 修改入口（追加） | 对已添加的基金，「修改」里只要有「取消定投」，不要有启用定投的操作 |
| 计划数量（追加） | 每个基金只能存在一个定投计划 |
| 同代码合并（追加） | 定投与普通持有两类录入按基金代码自动合并，持有列表里一个代码只能有一条记录；再次用普通持有录入同一代码时应直接叠加到已有条目 |
| 结算口径（追加） | 持有基金允许一定时间内用估算值展示，但在下一交易日开始前必须以官方净值准确更新完毕（详见 `docs/fund-nav-settlement-plan.md`） |

## 2. 目标

- 启用计划后，持有金额与累计收益不再手填，而是按「计划参数 + 历史净值」按期派生。
- 中途停机不需要补跑任何任务：重启后按同一份净值重算，结果与「一直在线」完全一致。
- 保留手动校准：用户看到与实际不符时，可以把实际持有金额与实际累计收益折算成基线覆盖。
- 不猜测：净值或行情取不到时，受影响的金额字段留空（显示占位），不用 0 冒充。

## 3. 关键设计决策：计划驱动派生，而不是台账累加

两种可行做法的对比：

| 方案 | 停机期间 | 手动校对 | 一致性 |
| --- | --- | --- | --- |
| 台账累加（每次扣款往持仓上加一笔） | 必须补跑漏掉的任务，否则期数与金额永久缺失 | 需要「增量对账」，改一次历史期次就要回滚 | 依赖运行状态，任务漏跑就不可恢复 |
| **计划驱动派生（本方案）** | 无需补跑：账本是纯函数，重启后重算即完整 | 用「基线快照」覆盖，可预测 | 只依赖计划参数与净值数据，天然幂等 |

因此本方案把持有金额做成**派生值**：`f(计划参数, 历史净值) → 期数 / 累计投入 / 份额`，不落库任何中间状态。这也顺带解决了「服务器中断需要看门狗补跑」的诉求——本功能没有需要守护的定时任务。

## 4. 数据模型

`fund_positions` 新增 7 列（迁移 `drizzle/0012_absurd_paper_doll.sql`，本地 JSON 回退同结构）：

（净值结算补充了 `calib_nav` / `calib_anchor` 两列，见 `docs/fund-nav-settlement-plan.md` §3。`calib_anchor = estimate` 表示基线锚定在估算值上、官方净值公布后按官方口径重锚。）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `dca_frequency` | text | `daily` / `weekly` / `biweekly` / `monthly`；非空即表示启用计划 |
| `dca_weekday` | integer | 每周定投的星期几（1–5）；非 weekly 为 null |
| `dca_amount` | numeric(18,2) | 每期投入金额，必须大于 0 |
| `dca_start_date` | text | 计划启用日（首期目标日），YYYY-MM-DD |
| `calib_nav_date` | text | 手动校准采用的净值日 |
| `calib_shares` | numeric(18,4) | 校准份额 = 校准持有金额 / 校准日净值 |
| `calib_cost` | numeric(18,2) | 校准本金 = 校准持有金额 − 校准累计收益 |

约定：

- `plan` 非空即「该持仓由计划派生」，此时 `amount` / `profit` 落 0（不再有语义）。
- `calibration` 非空表示用户手动校准过；校准日（含）之前的期次不再重复计入。
- 未启用计划的记录 `plan` 与 `calibration` 均为 null，行为与既有手动持仓完全一致。

## 5. 账本计算（`src/lib/fund-dca-plan.ts`，纯函数）

### 5.1 目标日序列

- 首期 = 启用日；之后按频率推进到「今天（含）」。
- 每日 +1 天；每周 +7 天；每两周 +14 天；每月 +1 个月（目标月天数不足时收敛到月末，如 1-31 → 2-28）。
- 每周定投先锚定到「不早于启用日的第一个所选星期几」，再每 7 天一期。
- 期数上限 `MAX_PLAN_PERIODS = 2000`（按每日定投约 8 年），防止异常参数造成超长循环。

### 5.2 实际扣款净值日

每个目标日取「**不晚于该目标日的最近一个可用净值日**」的净值：

- 好处一：定投日当天就能看到本期已计入；当晚公布真实净值后自动修正，不需要任何补偿逻辑。
- 好处二：遇非交易日（周末 / 节假日）自动顺延到上一个净值日，不需要交易日历。
- 只采用来源可用的净值（排除 `deterministic-fallback` 这类确定性降级数据），避免把演示数据当成真实净值。

### 5.3 账本公式

```
期次 periods   = 目标日序列排除「校准日（含）之前」的期次后的条数
累计投入 invested = 校准本金 + 期次 × 每期金额
持仓份额 shares  = 校准份额 + Σ(每期金额 / 该期实际单位净值)
```

## 6. 估值与口径（`valuePlanFundPosition`）

```
上一交易日市值 = 份额 × 上一交易日官方单位净值
当前市值       = 份额 × 实时估值净值（取不到时回落官方净值）
当日收益       = 当前市值 − 上一交易日市值（取不到实时估值时留空，不用 0 冒充）
累计收益       = 当前市值 − 累计投入
累计收益率     = 累计收益 / 累计投入
持仓占比       = 当前市值 / Σ当前市值
```

- 计划持仓的 `profit_caliber` 恒为 `include_today`：份额 × 净值本身就是「已含当日」的口径，不存在两种语义。
- 「当日收益」两种情况都给值：拿到**盘中估算 / 场内实时**净值时按估算推算；当天官方净值已公布时改用官方净值精确推算（`当日涨跌幅 = 今日官方净值 / 昨收净值 − 1`）。两者都取不到时留空，避免把收盘后的 0 当成「今天没赚没亏」（结算规则见 `docs/fund-nav-settlement-plan.md`）。
- 净值区间按「起点（校准日或启用日）→ 今天」的跨度选择（`1m` / `3m` / `6m` / `1y` / `3y` / `all`），不做全量拉取。

## 7. 手动校准

用户填写「实际持有金额 + 实际累计收益」后，系统按当前净值折算：

```
基准净值 nav    = 今天的官方净值优先（官方口径，无需结算）；未公布时用今天的估算 / 实时价（净值日 = 今天，标记 anchor = estimate，待官方净值公布后重锚）；两者都取不到时退回最近公布的官方净值（周末与节假日录入即为此情形）
校准份额 shares = 实际持有金额 / 基准净值
校准本金 cost   = 实际持有金额 − 实际累计收益
```

- 校准日（含）之前的期次不再重复计入，之后继续按期累加。
- 估算锚定的基线在锚定日官方净值可取到时，按 `新份额 = 原份额 × 估算锚定净值 / 官方净值` 自动重锚（本金与净值日不变）：读接口即时生效，每晚 `FUND_SETTLE_CRON` 的「净值结算」任务负责把结果落库；官方净值仍未公布时界面标注「待结算」，不用估算冒充官方。
- 取不到净值时接口返回 400「暂时取不到该基金的净值，无法完成校准，请稍后重试。」，不会写入半成品基线。
- 传 `calibration: null` 可清除校准，回到纯计划派生。

## 8. 接口

- `POST /api/fund-positions`：新增录入，**按基金代码合并**（持有列表里一个代码只保留一条记录，创建 201 / 合并 200）。
  - 代码不存在 → 新建。
  - 已存在且两边都是普通持有 → 持有金额与累计收益**叠加**；口径必须一致，否则 409 拒绝（两种语义的金额不能相加）。
  - 已存在普通持有 + 本次是定投 → 在既有条目上启用计划，并把既有录入值折算成校准基线，已录入的持有不会凭空消失。
  - 已存在定投 + 本次是定投 → 更新这一个计划的参数（一个基金只能有一个计划），已有校准保留。
  - 已存在定投 + 本次是普通持有 → 409，提示先在「修改」里取消定投。
- `PATCH /api/fund-positions/:id`：
  - `plan` **只接受 `null`**（取消定投）：此时必须同时提交 `amount` 与 `profit` 以固化为手动持仓，并一并清除校准基线；传计划对象返回 400 并提示去「添加」里录入。
  - `calibration` 传对象 = 按实际值校准；传 `null` = 清除校准。
- 校验失败统一 `400 VALIDATION_ERROR`（合并冲突用 409），文案面向用户（中文、可操作）。

## 9. 界面（`FundPositionsPanel`）

- **录入表单是唯一能启用 / 调整计划的地方**；输入已在列表中的代码时，表单下方提前提示本次提交会「叠加 / 折算基线 / 更新计划 / 被口径不一致拒绝」，提交成功后给出行内提示（不弹窗，便于连续录入）。
- 录入表单：「启用定投计划」勾选后，持有金额 / 累计收益 / 口径三个输入框替换为「定投频率 + 扣款日（每周时出现）+ 每期金额 + 启用日（留空 = 今天）」。
- 列表：计划持仓在基金名旁显示「定投」小标，名称下方显示计划摘要（频率 / 每周几 / 每期金额 / 启用日）；持有金额格显示「累计投入」与「定投 N 期 · 份额 X」。
- 修改（行内展开）**只保留取消定投**，不再提供启用 / 调整计划的操作：
  - 「累计收益口径」下拉：计划持仓时为禁用，点「取消定投」后才可切换。
  - 计划持仓显示计划摘要 + 「取消定投」按钮（可再点一次撤回）；确认取消后，上表两格（已预填当前派生值）会被固化为手动持仓，保存前可修正。
  - 手动持仓显示一行指引：如需改成定投，请在「添加持有基金」里用同一代码提交。
  - 「手动校准（可选）」：实际持有金额 + 实际累计收益；已校准时显示当前基线并提供「清除校准」。
- 收益类数字为正时前缀「+」（与涨红跌绿配套）；取不到时显示占位而不是 0。

## 10. 边界与不做的事

- 不回溯启用日之前的期次，不建模底仓、不做份额对账。
- 不处理分红、申购赎回、份额折算造成的份额变动（与既有口径模型一致）；这类变动请用手动校准覆盖。
- 不区分非交易日：目标日遇非交易日顺延到上一个净值日（不是下一个），因此期数不会因节假日漂移。
- 计划持仓的「当日涨跌幅」仍展示基金本身的盘中涨跌幅，与持仓金额无关。
- 取消定投会把当前派生值固化为手动持仓（而不是删掉记录）；之后想恢复定投，用同一代码在「添加」里重新提交即可，届时既有持仓会重新折算成校准基线。
- 同一代码有两种录入方式但只有一条记录：定投持仓不能再叠加手动金额（会提示先取消定投），避免计划派生金额与手动金额混在一起。
