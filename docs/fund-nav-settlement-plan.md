# 持有基金：估算值展示窗口与官方净值结算方案

- 文档版本：v1.1（2026-09-15，新增 R6 手动持仓跨日滚存）
- 关联文档：`docs/fund-dca-plan-tracking-plan.md`（定投账本与手动校准，本方案补充其 §6 / §7 的净值口径）、`docs/fund-position-caliber-plan.md`（配对口径模型）、根 `checklist.md`
- 分支：`feature/fund-dca-plan`
- 需求原文：持有基金中，允许一定时间内使用估算值展示，但在下一交易日开始前一定要以官方净值准确更新完毕。

## 1. 术语与现状

| 术语 | 含义 | 现有字段 |
| --- | --- | --- |
| 估算值 | 场外盘中估算净值 / 场内实时价，交易时段内可近似当日盈亏 | `nav_mode = estimate / realtime` |
| 官净值 | 基金公司公布的当日单位净值（净值日 = 当天），收盘后陆续公布 | 历史净值序列中 `nav_date = 今天` 的点 |
| 结算 | 当日数据以官方净值为准落定，不再使用估算值 | 本次新增 |

现状问题（实测）：

1. 手动持仓的计价来源**永远优先估算**：`resolvePricingSource` 先看盘中行情，即便当天官方净值已经公布，界面仍展示估算值与估算当日收益。
2. 估算值**可以跨日**参与展示：没有「抓取时间必须属于北京今天」的约束，上游出现陈旧 payload 时会把昨天的估算当成实时值。
3. 净值缓存 6 小时，且不区分「最新点是不是今天」：晚上 17:00 抓过一次（拿到昨天的净值），20:30 官方净值公布后再次进页面仍读缓存，看不到今天已公布的真实净值。
4. 定投校准基线（`calibration`）在启用计划时按 `resolvePricingSource` 取数，**估算会被写进持久化基线**，误差永久留在账本里。
5. 计划持仓当日官方净值公布后，当日收益直接留空（`settledToday` 分支），没有换成「用官方净值精确推算」。
6. 手动持仓的 `amount` / `profit` 是**静态快照**：只记录录入当天的口径，没有任何跨日推进机制，因此「上一交易日累计收益」永远停在录入那天的数值。实测 2026-09-14 以「不含当日」录入 021533（持有 400.07、累计收益 +0.07）后，09-15 打开页面时上一交易日累计收益仍是 +0.07，09-14 的收益没有进来。

## 2. 结算规则（R1–R5）

- **R1 官方优先**：净值序列里存在「今天」的官方单位净值时，当日涨跌幅、当日收益、估值口径一律改用官方净值推算，盘中估算不再参与展示。
  ```
  当日涨跌幅 = 今日官方单位净值 / 昨收净值 − 1
  昨收净值   = 严格早于今天的最近一个可用净值日（沿用 resolvePrevTradingNav）
  ```
  场内（`realtime`）同属该规则：收盘后以官方净值结算，盘中仍显示实时价。
- **R2 估算不跨日**：估算值只有在「抓取时间落在北京今天」时才可用于展示；跨日的估算（含场内实时价）一律视为不可用，回落到官方净值。上游返回陈旧数据时不会污染界面。
- **R3 窗口内允许估算**：当天官方净值尚未公布时，照旧展示估算净值与估算当日收益，并在界面标注口径（「盘中估算」/「场内实时」）。
- **R4 基线不锁定估算**：手动校准与「普通持仓转为定投」的折算基线优先锚定**今天的官方净值**（官方口径，无需结算）；今天官方净值尚未公布时用今天的估算 / 实时价锚定，并记录锚点来源 `anchor = "estimate"`（待结算）；两者都取不到时退回最近公布的官方净值（周末 / 节假日录入即为此情形）。
- **R5 下一交易日前结算完毕**：
  - **读时投影（保底）**：估算锚定的校准，一旦锚定日的官方净值可取到，立即按 `新份额 = 原份额 × 估算锚定净值 / 锚定日官方净值` 重锚（本金不变、净值日不变），纯计算即可完成，停机也不会漏。
  - **定时结算（落库）**：每交易日 21:30（`FUND_SETTLE_CRON`）执行「净值结算」任务，对全部持有基金强制刷新官方净值，并把仍为估算锚点的校准重锚后写回，次日打开页面即为官方口径。
  - **上游缺失**：官方净值在下一交易日开盘前仍未公布时，界面标注「待结算」，用估算值展示但明确提示，不冒充官方。

- **R6 手动持仓跨日滚存**：手动录入值是「某一天收盘口径」的一组快照，用 `manual_anchor{ nav_date, nav, source }` 记录它的层级：
  ```
  结算锚点：估算锚定 + 锚定日官方净值可取到 → 市值 ×= 官方 / 估算，累计收益平移同样金额（本金不变）
  推进    ：市值 ×= 目标收盘净值 / 锚定净值，累计收益平移同样金额（本金不变）
  目标日  ：读时 = 严格早于今天的最近收盘日（当日涨跌幅由展示层单独叠加）
            定时结算 = 已公布的最新收盘日（今天已公布取今天，否则取昨天）
  ```
  - **展示口径**：记录值锚在「今天之前」的收盘口径上时按 `exclude_today` 展示（当前市值 = 记录值 ×（1 + 当日涨跌幅），上一交易日市值 = 记录值）；只有锚在今天的当前值上（当天录入且尚未跨日）才按 `include_today` 展示。取不到当日涨跌幅时回落到录入口径，避免把已有数字显示成空。
  - **录入锚点**（`resolveManualAnchorSnapshot`）：「不含当日」锚在严格早于录入日的最近收盘日；「含当日」优先录入日官方净值，其次录入日盘中估算（`estimate`，待官方公布后重锚），最后回落到录入日之前最近的收盘日（周末 / 节假日录入，录入值就是上一个收盘口径）。
  - **合并与修改**：同一代码再次录入时，先把既有记录推进到「更靠后的锚点」层级再叠加（避免把已结算的旧值再滚一遍）；「修改」里金额 / 累计收益 / 口径变化时按今天的口径重新锚定，只改备注等字段则固化当前生效锚点，避免 `updated_at` 变化后按新日期重新推断。
  - **落库**：定时结算任务把推进结果（金额 + 累计收益 + 锚点）写回；估算锚点在官方净值公布前计入「待结算」，与 R5 同口径，不用估算冒充官方。

## 3. 数据模型

`fund_positions` 新增 4 列（迁移 `drizzle/0013_*.sql`、`drizzle/0014_*.sql`，本地 JSON 回退同结构）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `calib_anchor` | text | 校准基线锚点来源：`official`（官方净值）/ `estimate`（估算锚定，待结算）；null 视为 `official`（兼容历史数据） |
| `manual_anchor_date` | text | 手动持仓锚点对应的净值日（YYYY-MM-DD）；null 表示按录入时间推断（历史数据） |
| `manual_anchor_nav` | numeric(18,4) | 手动持仓锚定净值：官方锚定为官方单位净值，估算锚定为盘中估算 / 实时价 |
| `manual_anchor_source` | text | 手动持仓锚点来源：`official` / `estimate`（估算锚定，待官方净值公布后重锚） |

`FundPositionValuation` 新增字段：

| 字段 | 说明 |
| --- | --- |
| `settlement_pending` | 该持仓的校准基线 / 手动锚点仍锚定在估算值上、且锚定日的官方净值尚未取到（界面标注「待结算」） |
| `nav_date` | 本次展示采用的官方净值日（`nav_mode = "nav"` 时为今天，否则为最近公布的净值日） |
| `display_caliber` | 本次展示实际使用的口径（R6）：锚在今天的当前值上为 `include_today`，否则 `exclude_today`；`profit_caliber` 仍回显用户录入的口径 |

## 4. 缓存与取数

- `getFundNav` 缓存 TTL 条件化：最新净值点属于今天 → 6 小时（当天不会再变）；否则 10 分钟（官方净值随时可能公布，不能在窗口期内缓存 6 小时）。
- 结算任务通过 `getFundNav(code, range, "unit", true)` 强制刷新，绕过上述缓存。

## 5. 界面

- 「实时估值」列：`nav_mode = nav` 时该列为空（官方净值即当前价，另列展示），并标注「官方净值」；`estimate / realtime` 标注对应口径与抓取时间。
- 计划持仓在官方净值未公布时显示「盘中估算 · 待结算」提示；结算完成后提示消失。
- 汇总区「净值结算状态」：全部已结算 / N 只待结算（官方净值未公布，含手动持仓的估算锚点）。
- 手动持仓「修改」表单：金额与累计收益按**展示口径的层级**预填（不含当日填上一交易日口径），并提示当前展示口径；直接保存不会重复计算当日涨跌，改了数字才按今天的口径重新锚定。

## 6. 不做的事

- 不引入交易日历判断「是否已过结算时刻」，结算只依赖「今天的官方净值是否已公布」。
- 不修改估值公式本身（市值 = 份额 × 净值、当日收益 = 现价市值 − 昨收市值），只更换净值来源。
- 不为估算值做补偿或回归修正：估算只展示，不进入持久化基线。
- 不按交易时段收窄估算窗口：估算值只要「抓取时间属于今天」就允许展示（QDII 的盘中估值本身跨时区），只在当天官方净值公布后强制切到官方口径。
- 不回溯改写录入当天之前的收益：录入当天不补当日收益（当天录入即当天口径），推进从下一个交易日起生效。
- 不做逐日连乘：按「目标收盘净值 / 锚定净值」一步折算，避免中间取整漂移；推算本金（金额 − 累计收益）在推进前后恒等。
